烧饼商品小程序 —— 新增深挖需求（5 项）

【最高优先级】后端未启动，全量 Mock 数据实现。页面必须可见、可交互、数据真实呈现，无白屏/报错/裂图/死链。


一、限时抢购模块

1.1 首页抢购区（pages/index/index）
- 在轮播图下方新增「限时抢购」模块
- 场次条：10:00 / 14:00 / 20:00 三场，当前场高亮
- 倒计时：时:分:秒实时递减，到期自动切下一场
- 横滑商品卡：抢购价（红色加粗） + 原价划线 + 已抢 xx% 进度条 + 剩余库存
- 「马上抢」按钮：弹 SKU 选规格 → 按抢购价加购

1.2 抢购规则
- 每场 6-8 个抢购商品，限时 2 小时
- 每人每场每商品限购 1 件
- 进度条样式：主题色渐变 + 百分比文字
- 抢光/到期显示「已抢光」/「已结束」置灰

Mock：每场独立商品列表，初始进度 20%-80% 不等


二、优惠券系统

2.1 领券中心（新增 pages/coupon/index）
- 券卡列表：左侧大号面额 + 右侧门槛/有效期/适用范围
- 类型标识：满减券（红色）/ 折扣券（橙色）/ 无门槛券（金色）
- 「立即领取」按钮：点击写入 storage（user_coupons 数组），每人每券限领 1 张，已领置灰
- 空态：「优惠券已被领完，下次早点来~」

2.2 我的优惠券
- 入口：我的页菜单「我的优惠券」
- Tab 切换：未使用 / 已使用 / 已过期
- 券卡：面额大字 + 门槛描述 + 有效期倒计时（临期红色标识）
- 「去使用」：跳首页或分类页

2.3 下单联动（支付确认页）
- 自动匹配最优可用券（满足门槛且优惠金额最大）
- 券列表弹层：可用券勾选、不可用券置灰 + 原因说明（"未满 59 元"）
- 用券后金额明细重算（商品总价 - 优惠券 - 满减 = 实付）

Mock：8-10 张券模板（5 张满减 + 2 张折扣 + 1 张无门槛），用户初始持 4 张


三、会员积分体系

3.1 积分获取规则（Mock）
- 购物：每 1 元 = 1 积分
- 每日签到：+5 积分（见深挖 4）
- 订单评价：+20 积分
- 积分实时写入 storage（user_points 字段 + points_records 数组）

3.2 积分中心（新增 pages/points/index）
- 头部积分卡：当前可用积分（大字）+ 「签到赚积分」入口
- 积分明细列表：+绿色 / -红色，来源（购物/签到/评价/兑换）+ 时间，分页
- 积分兑换专区（4-6 个兑换项）：
  · 100 积分 → 满 30 减 5 券
  · 200 积分 → 满 50 减 10 券
  · 500 积分 → 满 99 减 25 券
  · 800 积分 → 指定商品免费兑换
- 兑换流程：二次确认 → 扣积分 → 券到账 → toast「兑换成功」
- 积分不足时按钮置灰显示「积分不够」

Mock：用户初始积分 680，积分记录 15+ 条


四、每日签到

4.1 签到页面（新增 pages/checkin/index）
- 入口：我的页菜单「每日签到」（未签到显示红点）
- 当月签到日历：7 列网格，已签日期主题色圆点 + ✓，今日高亮描边，未来日期灰色
- 签到按钮：今日未签可点（点击弹出签到成功弹层 + 积分 +5 动画），已签置灰「今日已签到 ✓」
- 连续签到奖励条：第 1-7 天梯度横排展示（+5 / +5 / +10 / +10 / +15 / +20 / +50）
- 当前连续天数 + 断签规则说明
- 日历支持左右翻月查看历史

4.2 签到规则
- 每天限签 1 次
- 断签重新从第 1 天计算
- 连签第 7 天大奖 +50 积分 + 弹层特效
- 签到数据 storage 持久化（连续天数 + 当月已签日期数组）

Mock：用户连签 3 天，当月已签 8 天


五、消息通知中心

5.1 消息列表（新增 pages/message/index）
- 入口：我的页菜单「消息中心」
- 列表：类型图标 + 标题 + 摘要（一行省略） + 相对时间 + 未读红点
- 类型 Tab：全部 / 订单 / 促销 / 系统
- 点击消息标记已读 + 跳转关联页：
  · 订单消息 → 订单详情
  · 促销消息 → 领券中心 / 抢购区
  · 系统消息 → 就地展开查看
- 顶部「全部已读」按钮
- 空态：「暂无消息」

5.2 未读角标
- TabBar「我的」图标展示未读消息数（wx.setTabBarBadge）
- 进入消息页或点击「全部已读」后清零

5.3 Mock 推送场景
- 进入消息中心后延迟 3 秒自动 push 一条促销消息
- 下单后自动写入一条订单消息
- 券临期 24 小时自动生成过期提醒消息
- 写入 storage（messages 数组），未读数实时计算

5.4 消息数据模型
  id, type（1系统/2订单/3促销）, title, content, isRead, createTime, relatedId（关联跳转）

Mock：初始 15+ 条消息，分布各类型，3 条未读
